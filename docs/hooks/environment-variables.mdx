The following environment variables are available in all agent bash tool executions, including [init hooks](/hooks/init).

## Available Variables

| Variable             | Description                                                                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `XUM_PROJECT_PATH`   | Absolute path to the project root on the **local machine**. Always refers to your local project path, even on SSH workspaces. |
| `XUM_RUNTIME`        | Runtime type: `"local"`, `"worktree"`, `"ssh"`, or `"docker"`                                                                 |
| `XUM_WORKSPACE_NAME` | Name of the workspace (typically the branch name)                                                                             |
| `XUM_MODEL_STRING`   | Model identifier (e.g., `"anthropic:claude-sonnet-4-20250514"`)                                                               |
| `XUM_THINKING_LEVEL` | Reasoning level: `"off"`, `"low"`, `"medium"`, `"high"`, or `"xhigh"`                                                         |
| `XUM_COSTS_USD`      | Cumulative session costs in USD, formatted to 2 decimal places (e.g., `"1.23"`)                                               |

Matching `MUX_*` names remain accepted aliases. When both are set, the `XUM_*` value wins. See [Mux compatibility](/reference/mux-compatibility).

## Usage Example

```bash
#!/usr/bin/env bash

echo "Project: $XUM_PROJECT_PATH"
echo "Runtime: $XUM_RUNTIME"
echo "Workspace: $XUM_WORKSPACE_NAME"
echo "Model: $XUM_MODEL_STRING"
echo "Thinking: $XUM_THINKING_LEVEL"
echo "Costs: \$${XUM_COSTS_USD:-0.00}"

# Runtime-specific behavior
if [ "$XUM_RUNTIME" = "ssh" ]; then
  echo "Running on SSH remote"
elif [ "$XUM_RUNTIME" = "docker" ]; then
  echo "Running in Docker container"
else
  echo "Running locally"
fi
```

## Use Cases

- **PR footers**: Include model and cost information in automated PR descriptions
- **Conditional logic**: Adapt scripts based on runtime environment
- **Logging**: Track which model and settings were used for a task
- **Cost monitoring**: Check cumulative costs before expensive operations
